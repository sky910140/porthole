# 舷窗 Porthole 初学者操作手册

适用：Porthole 0.9.0、Windows x64、VS Code、ChatGPT 网页版。核对日期：2026 年 10 月 7 日。

**第一次使用按下面 7 步操作；连接成功后，日常只需要打开 VS Code、选择项目、在 ChatGPT 提问。**

本手册使用推荐的“私有隧道”方式。无需运行 PowerShell，也无需配置域名、HTTPS 转发或 GitHub OAuth App。首次仍需在 OpenAI Platform 创建隧道和运行密钥，并在 ChatGPT 添加一次应用。

下载 [porthole-0.9.0.vsix](https://github.com/sky910140/porthole/releases/tag/v0.9.0)，按下面步骤安装。

## 先看自己做到哪一步

| 你现在看到的状态 | 从哪里继续 |
|---|---|
| 还没安装 Porthole | 从第 1 步开始 |
| 首页显示“本机项目已就绪” | 从第 3 步开始 |
| “本机检查已通过”，真实工具调用“等待验证” | 从第 6 步开始 |
| “连接已验证” | 直接看“开始提问”和“日常使用” |

操作会用到三个地方：

| 页面 | 用来做什么 |
|---|---|
| VS Code 中的 Porthole | 安装服务、选择文件夹、查看连接状态 |
| OpenAI Platform | 创建 Tunnel ID 和运行 API Key |
| ChatGPT 网页的“插件”页 | 添加 Porthole，随后在对话里使用 |

## 第一次使用：7 步完成连接

### 第 1 步：安装并打开 Porthole

准备好 VS Code、从下载页取得的 `porthole-0.9.0.vsix` 安装包，以及能使用自定义 MCP 和隧道的 OpenAI 账号。

1. 打开 VS Code，按 `Ctrl+Shift+X` 打开“扩展”。
2. 点击扩展面板右上角 **… → 从 VSIX 安装**，选择安装包。
3. 按提示重新加载 VS Code。
4. 按 `Ctrl+Shift+P`，输入并运行 **舷窗: 打开首页**。
5. 点击 **安装本机服务**。

**成功标志：**“本机服务”区显示已安装版本，首页提示选择项目。首次安装后服务尚未运行是正常的；完成第 2 步授权后，工具会启动服务并连接。

已经安装过的用户，在首页点击 **检查并安装附带版本**。本手册对应“已安装 0.9.0；扩展附带 0.9.0”。只更新扩展，不代表本机服务也已更新。

### 第 2 步：选择要让 AI 读取的文件夹

1. 点击 **选择文件夹**；已有项目时，按钮可能叫 **选择其他文件夹**。
2. 在系统窗口里选择目标文件夹，例如 `D:\我的资料\示例项目`。
3. 核对弹窗中的完整路径，点击 **授权此目录**。
4. 点击 **重命名项目**，改成自己容易识别的名称，例如“示例项目”。这只改变显示名。
5. 点击 **预览可访问文件**，查看展开的 **可访问文件清单与排除原因**。

**成功标志：**本机服务显示运行中，首页显示正确目录、项目标识和文件清单。默认访问模式是“仅查看代码”，也可读取支持的资料文件；此时 AI 只能查看，不能通过本工具应用修改。

这里只共享所选目录中符合规则的已保存文件。未保存内容默认不共享；被读取的文件内容会交给 ChatGPT 处理。

清单超过 200 个文件时只展示部分，并提示是否扫描完整。看到数量后，可以展开清单查看具体文件；需要更新清单时点击 **重新预览**。

### 第 3 步：创建隧道，取得 Tunnel ID

1. 在首页点击 **连接 ChatGPT（推荐）**。
2. 在连接向导点击 **创建 / 查看 Tunnel**，打开 [OpenAI Platform 的 Tunnels 页面](https://platform.openai.com/settings/organization/tunnels)。
3. 登录用于连接的账号，点击 **Create tunnel**。
4. 按下面填写。

| 字段 | 怎么填 |
|---|---|
| Name | `Porthole` |
| Description | `让 ChatGPT 读取我授权的本机项目文件。` |
| Organizations | 选择创建和运行此隧道的 Platform 组织。个人使用选自己的个人组织；页面可能显示 Personal。记住这个组织，下一步在同一组织创建密钥。 |
| ChatGPT workspaces | 选择你准备使用 Porthole 的 ChatGPT 工作区。个人使用选对应个人工作区；团队使用选实际的团队工作区。名称以列表显示为准。 |

5. 点击 **Create**。
6. 复制生成的完整 **Tunnel ID**，通常以 `tunnel_` 开头。
7. 回到 VS Code，把它粘贴到连接向导的 **Tunnel ID** 输入框。

Tunnel ID 是隧道编号，不是项目名称、本机项目标识或 API Key。工作区关联决定隧道在哪个 ChatGPT 工作区可见；创建隧道需要组织侧 **Tunnels Read + Manage** 权限。[OpenAI 官方说明](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)

如果 ChatGPT workspaces 没有选项，先核对登录账号和目标工作区的关联，不要填写本地目录或 GitHub 用户名。团队账号可能需要管理员处理关联和权限。

### 第 4 步：创建运行密钥

1. 回到 VS Code 连接向导，点击 **创建运行密钥**，打开 [OpenAI Platform 的 API Keys 页面](https://platform.openai.com/api-keys)。
2. 确认左下角组织与第 3 步一致。
3. 点击 **Create new secret key**，按下面填写。

| 字段 | 怎么填 |
|---|---|
| Owned by | 个人使用选 **You** |
| Name | `Porthole-Tunnel`，方便以后识别 |
| Project | 可以保留 **Default project**，前提是它属于刚才创建隧道的组织；这里不是本机文件夹。 |
| 有效期 | 建议选择 90 天（若列表提供）；否则选择合适期限，并记下到期日期。 |
| Permissions | 选择 **Restricted**，在具体权限中为 **Tunnels** 开启 **Read + Use**。其余不需要的权限设为 None。 |

运行密钥和账号本身都应具有所需的隧道访问权限。组织侧权限不会因为把密钥设为 All 而自动开通。[OpenAI 权限说明](https://developers.openai.com/api/docs/guides/rbac)

选择 Restricted 后，查看展开的权限列表。如果没有 Tunnels 项，先核对组织和账号权限，并保留不含密钥的界面用于排查；不要根据名称猜选其他权限。Read only 也不能代替运行隧道所需的 Use 权限。

4. 点击 **Create secret key**。
5. 复制生成的完整密钥，回到 VS Code，粘贴到 **运行 API Key** 输入框。

**密钥只填在本机工具的密钥输入框里，不发到聊天中。** 保存后工具不会回显密钥；以后留空可继续使用已保存密钥，填入新密钥则替换。到期前创建替代密钥并更新工具。[OpenAI 密钥有效期说明](https://developers.openai.com/api/docs/guides/production-best-practices)

### 第 5 步：保存并自动检查

在 VS Code 连接向导点击 **保存并自动检查**，等待页面更新。

| 检查项 | 此时应看到什么 |
|---|---|
| 本机 MCP 与项目授权 | 通过 |
| 隧道客户端 | 运行中 |
| 隧道服务认证与连接 | 通过 |
| ChatGPT 真实工具调用 | 等待验证 |

**成功标志：**页面显示“本机检查已通过，继续在 ChatGPT 添加应用”。

最后一项此时“等待验证”是正常的，继续第 6 步。本机检查通过，还需要在 ChatGPT 完成实际调用。

### 第 6 步：在 ChatGPT 添加应用

1. 在 VS Code 点击 **复制 Tunnel ID**，然后点击 **打开 ChatGPT 插件页**。
2. 在 ChatGPT 网页右上角点击 **添加**。
3. 选择 **创建自定义 MCP 服务器**。部分界面叫 **创建 MCP 应用**，都是本手册使用的入口。
4. 在弹窗“连接”一栏，先点击右侧 **隧道**，再填写下面的内容。

| 字段 | 怎么填 |
|---|---|
| 图标 | 可以留空 |
| 名称 | `Porthole` |
| 描述 | `读取我授权的本机项目文件` |
| 连接方式 | **隧道（Tunnel）** |
| Tunnel ID | 粘贴刚从 VS Code 复制的完整 ID，或选择对应隧道。 |
| 身份验证 | 将默认的 OAuth 改为 **无（None / No authentication）** |
| 高级 OAuth 设置 | 选择“无”后，无需配置。 |

5. 查看页面提示，勾选 **我已了解，并希望继续**。
6. 点击 **以插件形式创建**；部分界面按钮叫 **创建**。
7. 如果页面继续提示“安装”或“连接”，按提示完成。
8. 新建 ChatGPT 对话，在输入框输入 `@`，选择刚创建的 **Porthole**。

**成功标志：**应用已创建并安装，且新对话中选中了它。具体添加和选择插件的方法见 [OpenAI 官方操作说明](https://developers.openai.com/api/docs/guides/custom-mcp-server)。

这里填写的是 Tunnel ID。运行 API Key 已由本机工具保存，不填到 ChatGPT 的表单或对话中。

如果你已经能打开这个创建弹窗，直接继续，不必再寻找开发者模式开关。没有入口时，使用 ChatGPT 网页，并检查当前工作区是否允许添加自定义 MCP；账号权限由平台或工作区管理员决定。

有旧的“Porthole 新连接”时，名称本身不决定连接是否正确。核对应用使用的 Tunnel ID，选中本次创建的应用。后续新建对话，也需要确认选中它。

### 第 7 步：发送验证提示词

1. 保持 VS Code 开着，回到连接向导。
2. 在“确认真实连接”区域点击 **复制验证提示词**。
3. 切回刚才选中 Porthole 的 ChatGPT 对话。
4. 将提示词原样粘贴并发送，不修改其中的项目标识或挑战编号。
5. 等待工具调用完成，VS Code 页面会自动确认结果。

**成功标志：**连接向导显示 **连接已验证**，且“ChatGPT 真实工具调用”显示 **通过**。工具结果可能包含 `"verified": true`。

如果提示词过期，重新点击复制，再发送新提示词。验证时为确认读取而只取少量文件；结果中的 `has_more: true` 或 `page_limit` 不代表连接失败。

## 开始提问

验证后，在连接向导点击 **复制项目提问模板**，发到已选中 Porthole 的 ChatGPT 对话。模板会带上当前项目标识，帮助 AI 选择正确项目。

之后可以接着这样问：

```text
请使用舷窗 Porthole，基于刚才选择的项目，列出可以读取的文件，
读取主要资料后介绍项目用途。请标注依据的文件路径；读取失败时说明原因。
```

```text
请使用舷窗 Porthole 的 read_table，读取项目中的“示例清单.xlsx”，
先列出工作表，再分批读取相关数据，汇总主要内容。请说明读取范围。
```

| 文件类型 | 当前怎么读取 |
|---|---|
| 文本、代码、Markdown 等 | 使用 `read_file` 按段读取 |
| UTF-8 CSV、XLSX | 使用 `read_table` 分批读取；不计算公式 |
| PDF、图片、旧版 XLS 等 | 当前版本暂不解析内容 |

读取有文件大小和输出数量限制。AI 看到清单，不代表已经读完所有文件；回答应标出实际读取的文件和范围。需要更多内容时让它继续读取。

## 日常使用：只做 3 件事

1. **打开 VS Code。** 保持本机服务和扩展运行；手动停止服务后，需要点击“启动服务”。
2. **确认项目。** 在首页“当前查看”选择目标项目，核对目录；改读其他目录时点击“选择其他文件夹”并授权。
3. **在 ChatGPT 提问。** 新对话选中 Porthole；切换项目后重新复制项目提问模板。

切换已有项目或增加文件夹，通常不需要重新创建隧道和 API Key。若状态要求验证，重新复制验证提示词发送即可。

关闭 VS Code 或电脑休眠时，网页连接可能中断。重新打开后工具会尝试恢复已保存连接。开机自动启动目前只启动本机服务，使用私有隧道仍需保持 VS Code 扩展运行。

## 可选：让 AI 提出修改

只需阅读和分析资料时，保持默认只读即可。需要修改代码时：

1. 在 VS Code 首页确认选中了正确项目，开启 **允许提出修改**。
2. 再开启 **允许本机应用**，确认授权提示。
3. 在 ChatGPT 让 AI 通过 `propose_changes` 提交修改建议，并返回修改编号。
4. 在 VS Code 按 `Ctrl+Shift+P`，运行 **舷窗: 查看修改建议**，选择或输入编号，逐文件检查差异。
5. 检查无误后运行 **舷窗: 应用已审阅修改**。应用后运行项目自己的测试。

网页返回修改编号时，文件仍未改变。只有在 VS Code 明确应用后才会写入。出现未保存内容或文件版本变化提示时，按提示处理后重新审阅。

## 常见问题：按状态处理

| 看到的情况 | 下一步 |
|---|---|
| 已安装版本低于扩展附带版本 | 点击首页“检查并安装附带版本”，等待升级完成。 |
| 本机服务“已停止” | 点击“启动服务”，再检查连接。 |
| 点预览只看到数量，没有文件清单 | 确认扩展和服务都为 0.9.0；点击预览，展开“可访问文件清单与排除原因”。扫描失败时点“重新预览”。 |
| 本机检查都通过，但真实调用“等待验证” | 在 ChatGPT 添加并选中当前应用，发送刚复制的验证提示词。 |
| 看不到开发者模式或添加入口 | 使用 ChatGPT 网页检查“插件 → 添加”；若已有创建 MCP 弹窗，继续填写即可。没有入口时核对工作区权限。 |
| ChatGPT 没有列出隧道 | 核对隧道关联的 ChatGPT 工作区和当前账号的 Tunnels Read + Use 权限。 |
| 密钥无效或失效、401 | 展开向导“连接信息”，粘贴有效的完整新密钥，点击“保存并自动检查”。 |
| 隧道访问被拒绝、403 | 核对密钥所属组织、Tunnels 权限及账号本身的组织侧权限。 |
| Tunnel ID 不存在或不可见、404 | 从 Platform 重新复制完整 ID，并核对所属组织。 |
| ChatGPT 提示 UNAUTHORIZED 或要求重新授权 | 先核对是否选中了旧的 OAuth 应用。使用本次隧道对应的应用；旧连接在 ChatGPT 单独重新授权或移除。 |
| “网页验证已过期”或提示词过期 | 重新复制验证提示词并发送；验证过期不等于运行 API Key 已失效。 |
| 暂时断网或调用超时 | 保持 VS Code 开启，检查网络或代理，等待自动重连；仍失败时点击“检查连接”。 |
| XLSX 返回 binary file is not supported | 让 AI 改用 `read_table`。PDF、图片和旧版 XLS 暂不支持内容解析。 |
| 文件找不到或不可访问 | 核对项目目录、暂停状态和预览清单；磁盘读取需要文件先保存。 |
| 排查后仍失败 | 点击“检查连接”，按具体提示处理；需要反馈时导出脱敏诊断包，并附当前版本和失败步骤。 |

更详细的排查见 [排查指南](troubleshooting.md)。诊断包默认不包含源码、密钥、账号身份或本机路径。

## 想清除旧授权，重新开始

1. 在首页“检查与修复”点击 **恢复初始状态**。
2. 查看清理范围，确认一次，等待 **已恢复初始状态**。
3. 中途失败时点击 **继续恢复初始状态**，按提示继续。
4. 从第 2 步重新选择文件夹、授权并配置连接。

恢复会清除本机项目授权、连接设置和保存凭据，停止受管理服务及隧道。安装、项目文件、修改历史和恢复备份保留。

外部账号资源需另外处理：按完成页入口，在 ChatGPT 移除旧应用；在 Platform 撤销不再使用的密钥、删除不再使用的隧道。仅当以前使用过 GitHub OAuth 时，才需检查相应 GitHub 授权。本机恢复不会代你撤销这些外部资源。

详细清理范围见 [恢复说明](../extensions/vscode/RESET.md)。
