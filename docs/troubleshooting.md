# 常见问题与下一步

初学者先打开 VS Code 的 `舷窗: 打开首页`，点击“连接 ChatGPT”或“继续连接向导”。向导自动检查本机 MCP、项目授权、隧道客户端、隧道服务和真实工具调用。关闭后可继续；失败会显示原因。高级公网连接还显示 OAuth。上一层正常不代表下一层已通。诊断包可从首页导出，默认不包含项目绝对路径、令牌、源文件内容或 OAuth 返回。

| 看到的情况 | 下一步 |
|---|---|
| 本机服务未启动、端口占用 | 在首页点击“启动服务”或“检查连接”。端口冲突时先确认占用进程，不要结束不相关服务。开发者可运行 `scripts/status.ps1` 或查看本机状态目录的 `server.log`。 |
| 找不到 ChatGPT 的 Tunnel 选项 | 确认账号可使用开发者模式及 Secure MCP Tunnel，并把 Tunnel 关联到目标 ChatGPT 工作区；创建者需要 Tunnels Read + Use。该权限由 OpenAI 账号侧决定，扩展不能自动开通。可先只用本机功能，或使用“高级：公网连接”。 |
| 运行密钥无效或失效（401） | 在连接向导展开“连接信息”，粘贴完整的新 API Key，点击“保存并自动检查”。密钥不会回填；留空表示继续使用已保存密钥。 |
| 隧道访问被拒绝（403） | 核对运行密钥的 Tunnels Read + Use 权限、所属组织及 Tunnel 的可见性；修改后重新保存。 |
| Tunnel ID 不存在或不可见（404） | 从 Platform 的 Tunnels 页面重新复制完整 ID；核对组织。ID 草稿已保存，无需重填其他设置。 |
| 暂时无法访问隧道服务或限流 | 保持 VS Code 开启，检查网络和代理；运行中的官方客户端自动重连，页面自动更新。不需要重复点击保存。 |
| 隧道客户端已退出、连续失败暂停重启 | 返回首页重新启动隧道；若再次失败，在向导核对连接信息或导出诊断包。自动重启有次数限制。 |
| 扩展缺少运行包或 SHA-256 校验失败 | 重新安装完整 0.9.1 VSIX；安装包已附带官方客户端，首次启动无需下载。损坏归档不会自动降级或绕过校验。 |
| 私有隧道正常，但 ChatGPT 找不到项目 | 在 ChatGPT 选中使用当前 Tunnel ID 的 MCP 应用，发起 `verify_connection`；确认 VS Code 首页选中并授权了正确目录。仅显示隧道就绪不代表工具已调用。 |
| 网页找不到工具或超时 | 先确认本机服务，再确认 HTTPS 主机名仅指向 MCP 端口 8765。公网通道、账号权限和工具发现需在网页重新验证。 |
| OAuth 授权失效 | 在网页连接设置中重新授权；本机管理令牌与网页 OAuth 凭据不能互换。 |
| 状态显示“尚无真实工具调用” | 从网页发起 `verify_connection`，再读取已授权项目中的实际文件；只打开连接设置不算通过。 |
| 提示词等待中或已过期 | 将当前向导复制的提示词发到已选中 Porthole 的 ChatGPT 对话中；向导自动确认。过期后重新复制，不能复用旧提示词。 |
| 关闭 VS Code 后网页无法连接 | 当前私有隧道由扩展管理，需要保持 VS Code 开启；独立后台助手尚未实现。重新打开后扩展尝试恢复已保存连接。 |
| 看不到项目或文件 | 在管理页确认项目登记、根目录、暂停状态、模式和排除规则。`preview_scope` 可说明扫描预算与被排除原因。 |
| 网页返回修改编号，但文件未变 | 这是 `pending_review` 的正常状态。在 VS Code 运行“查看修改建议”，从待审阅列表选择；没有显示时粘贴编号。逐文件检查，再执行“应用已审阅修改”。网页要再次调用 `get_change_status`。 |
| 应用提示编辑器不可用或有未保存内容 | 打开绑定该项目的 VS Code 工作区，保存或关闭相关脏文档，重新审阅后再应用。失效租约需重新获取，不能沿用旧结果。 |
| `FILE_CHANGED` 或撤销冲突 | 原文件已有新变化。不要强制覆盖；查看当前差异，必要时重新提交建议。 |
| `recovery_required` | 暂停该项目的新修改，在管理页或 VS Code 查看恢复状态，保留原文件和诊断包。按提示执行安全恢复；未知后续内容不能自动覆盖。 |
| 修改存储不可用 | 检查磁盘空间、系统凭据存储和状态目录权限。SQLite 损坏时工具不会自动清空重建；先备份状态目录，再导出诊断。只读项目查询仍可使用时，不要把它误判为整个服务已离线。 |
| 升级后服务拒绝启动 | 查看 `upgrade-in-progress.json` 对应的快照编号。完成离线检查或使用 [升级恢复步骤](releasing.md)；不要直接删标记文件。 |

## 恢复初始状态遇到问题

| 提示 | 下一步 |
|---|---|
| `RESET_BUSY` | 完成或取消其他窗口中的连接配置、修改应用、撤销、恢复或升级，再重试；预检查失败不会清除授权。 |
| `RESET_INCOMPATIBLE` | 先点击首页“检查并安装附带版本”，升级正在运行的旧服务，再点击恢复。重置不会静默升级。 |
| `RESET_PENDING`、恢复中断 | 打开首页点击“继续恢复初始状态”。不要删除检查点；同一次恢复不必再次确认。 |
| `RESET_VAULT_UNAVAILABLE` | 解除 Windows 凭据管理器或 VS Code 凭据库的访问限制后继续；凭据未清除时不会报告成功。 |
| `RESET_PORT_IN_USE`、`RESET_STOP_FAILED` | 核对旧服务是否已停止；只停止确认属于本工具的进程，再继续。 |
| `RESET_UNSAFE_PATH` | 状态或配置路径包含目录链接；检查安装位置。工具不会跟随链接清理其他目录。 |
| `RESET_CONFIG_UNAVAILABLE`、`RESET_STATE_UNAVAILABLE` | 保留配置及恢复记录，检查权限、磁盘或配置格式；不要清空修改数据库来绕过错误。 |
| `RESET_FAILED` | 已保留恢复进度，点击继续；多次失败时使用脱敏诊断说明问题。 |
| 已完成，但 ChatGPT 中仍有旧应用 | 本机授权清除与外部账号撤销是两件操作。按 [恢复说明](../extensions/vscode/RESET.md) 在相应账号页面处理；完成页不会声称已撤销云端连接。 |

诊断或 Issue 请勿附带真实令牌、OAuth 返回、本地绝对路径或未经处理的项目代码。安全问题按 [安全策略](../SECURITY.md) 私密报告。
