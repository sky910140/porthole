# 0002：修改单状态与内容分离存储

日期：2026-09-21  
状态：采用

## 决策

修改单元数据、状态和幂等键存入 SQLite；拟写入文本和恢复备份存入加密的内容寻址 blob。数据库只保存内容 SHA-256 与 blob 标识，不保存明文正文。

内容密钥由可注入的提供者给出。Windows 运行时默认使用系统凭据后端；测试使用临时内存密钥。内容目录保存加密校验标记，密钥丢失、变化或标记缺失时停止修改功能，不删除数据库和 blob，也不创建空存储掩盖错误。

## 一致性边界

SQLite 与文件系统不能构成一次原子事务。接收修改单时先持久化加密 blob，再以 `BEGIN IMMEDIATE` 写数据库。数据库失败可能留下无引用 blob；清理器只删除超过宽限期且不被任何记录引用的对象。未解决的应用、撤销和恢复状态不会释放内容。

SQLite 使用 WAL、`synchronous=FULL`、外键和唯一幂等约束。备份通过 SQLite backup API 创建，再核验全部 blob 引用；不直接复制正在写入的数据库文件。

## 限制

- 最多 100 份未解决修改单；内容及备份默认总配额 1 GiB。
- 每单最多 20 个文件，单文件最终 UTF-8 内容最多 1 MiB，请求 JSON 最多 2 MiB。
- 待审阅单 24 小时后过期；终态内容保留 7 天，终态摘要保留 30 天；恢复项不自动清理。
