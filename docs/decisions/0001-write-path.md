# ADR 0001：网页提交修改单，本地审阅后统一应用

状态：已接受，2026-09-21。

## 背景

AI Zhagan 已有只读 MCP 和 VS Code 编辑器上下文。产品目标增加代码修改，但网页请求、编辑器缓冲区和磁盘文件属于不同生命周期。实际探针确认：文件在 VS Code 中 dirty 时，外部进程仍可改变磁盘，而编辑器保留另一份未保存内容。

## 决策

远程 MCP 只允许：

1. 读取授权范围；
2. 提交不可变修改单；
3. 查询修改单状态和有界差异。

只有本机管理接口能调用统一文件执行器。用户必须在 VS Code 中查看对应摘要哈希的差异并触发应用。应用前服务重新验证项目权限、文件字节哈希、编辑器就绪租约、操作幂等编号和状态修订号。

所有入口共用一个执行器。CLI、管理页面、扩展和 MCP 不得自行写项目文件。首版不开放删除、重命名、二进制修改或任意命令执行。

## 恢复规则

- 写前持久化事务类型、清单、原始内容和目标哈希。
- 每个文件用同目录临时文件替换，并记录逐文件阶段。
- 中断后以事务日志和当前字节哈希共同判定状态。
- dirty、编辑器暂时失联和租约过期保留待审阅状态；基准内容变化才进入冲突。
- 应用与撤销均有操作编号，超时重试先查询已保存结果。
- 无法确认安全恢复时进入 `recovery_required`，暂停该项目后续写入。

## 结果

好处是权限边界清楚、网页超时不会等同于写入失败、所有写入都可审阅和恢复。代价是用户需要回到 VS Code 点击应用，网页不能保证自动继续对话；跨文件修改也不是文件系统原子事务。

若真实集成测试无法满足保护要求，保留只读和补丁导出，暂不发布自动应用。
