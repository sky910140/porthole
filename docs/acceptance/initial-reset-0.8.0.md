# 0.8.0 恢复初始状态验收

2026-10-06 补充：首次启动及恢复完成后的首页空状态存在 `expiresAt` 读取错误，原 Extension Host 断言漏检了错误字段。已在 [0.8.1 修复验收](reset-home-hotfix-0.8.1.md) 中复现并修复；本报告保留 0.8.0 当时的检查记录。

日期：2026-10-04。环境：Windows 11 x64、Python 3.12.14、Node 24、VS Code 1.138.0。此版本为未公开发布、未签名的本机候选包。

## 本轮功能

- 首页“检查与修复”增加“恢复初始状态”，命令面板也可使用。一次确认后显示步骤进度；中断后点击“继续恢复初始状态”，同一次恢复不再重复确认。
- 清理本安装的全部项目授权、编辑器绑定、连接草稿、保存的 OAuth/Tunnel 凭据、配对及验证记录。停止拥有的服务与隧道，关闭本安装自启动，并更换本机管理/MCP 令牌。
- 保留安装版本、源码、业务文件、修改历史、加密内容及恢复备份。完成首页回到选择文件夹；外部 ChatGPT/GitHub/OpenAI 连接列出待处理入口，不声称已撤销。
- 活跃修改应用、撤销、恢复及升级阻止重置。配置编辑持有跨进程锁；其他窗口、后台恢复、失败回滚和旧快照不能放回已撤销授权。运行旧服务时明确提示先“检查并安装附带版本”。

## 审查与回归

独立审查报告的问题已修复：旧窗口回滚恢复授权、清理失败却提前确认回执、关闭目录的旧凭据清单在重启后丢失、服务准备失败时待完成标记未阻止新操作，以及另一个窗口清理成功后没有解除暂停。均有针对性回归；最后一项在真实 Extension Host 中先复现失败，再验证修复。

全套测试发现的版本不一致已改为统一版本来源。Windows 崩溃释放测试曾只终止虚拟环境启动器，现改为终止并等待真正持锁的解释器。测试夹具使用动态端口，退出时释放挂起的请求，避免端口冲突或清理阶段掩盖原始错误。打包扩展的确认测试仅在测试环境注入弹窗结果；公开命令仍使用真实确认。

最终包验收曾出现一次重置忙碌失败，后续完整与定向运行没有固定复现该错误；独立线程屏障实验确认状态查询存在配置锁竞争。已将慢安全检查移出状态查询的锁区间，重置最多等待锁 0.5 秒。新增 7 项回归先出现 5 项失败，修复后全部通过；持续编辑仍阻止重置，配置和凭据不被初始化。最终重建包的全套验收通过。旧上下文测试也加入活动编辑器确认、10 秒请求超时及脱敏阶段诊断，避免请求未发出时一直等待。

预检查可能创建配置相邻的协调锁文件；它不初始化凭据、不修改配置、项目或修改历史。恢复的检查点和回执只供本机使用，重置不作为 MCP 工具暴露。

## 构件与操作

安装包：`extensions/vscode/ai-zhagan-context-0.8.0.vsix`。大小及 SHA-256 以 `dist/candidate-manifest.json` 为准。

本次最终 VSIX：**59,264,380 bytes**；SHA-256：`eda2a7ca47f823b54aba26c575e7f160ca2da22625116c2fa9b464a17a05a4d6`。

核心 wheel：`dist/ai_zhagan-0.8.0-py3-none-any.whl`；独立程序：`artifacts/runtime/ai-zhagan-windows-x64.zip`。完整 VSIX 已包含程序和固定哈希官方隧道客户端。

在 VS Code“扩展 → … → 从 VSIX 安装”选择候选包并重载。首页先点击“检查并安装附带版本”，确认本机服务已升级；再点击“检查与修复 → 恢复初始状态”。操作范围与外部清理步骤见 [恢复说明](../../extensions/vscode/RESET.md)。
