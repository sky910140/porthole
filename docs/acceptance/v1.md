## 下一轮可执行验收

1. 在干净 Windows 11 x64 虚拟机，用未签名候选包完成三次安装、启动和卸载，再演练升级失败与恢复；确认项目源码目录未被清理。
2. 在维护者自己的公网入口和 OAuth 凭据下执行 [真实演示脚本](../demo-script.md)，录下安装到撤销的连续过程及每次网页状态查询；断连、重试、错误提示分别记录。
3. 招募上表参与者，按设计稿计时并修复卡点后复测。未参与者不能用开发者自己代填。
4. 固定 Windows 11 x64、4 核、16 GiB、SSD、10,000 个 UTF-8 小文件，记录 100 次读取 P95、20 次断连循环和 24 小时混合读写的时间序列、失败数与内存趋势。
5. 运行候选 GitHub Actions 工作流，复核第三方声明、签名状态、兼容矩阵、支持渠道与公开仓库范围。用户确认发布范围后才推送或创建 Release。

以上任一门禁未通过，都维持候选状态；尤其不能将待审阅误报为已写入，或以自动化替代真实网页账号与新用户试用。
