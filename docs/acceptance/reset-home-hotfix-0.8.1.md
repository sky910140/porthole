# 0.8.1 重置后首页空状态修复验收

日期：2026-10-06。此版本为本机未发布候选。

## 问题与原因

0.8.0 恢复初始状态后，项目授权和网页连接已清除，服务也已停止，但首页显示 `Cannot read properties of undefined (reading 'expiresAt')`。

首页刷新时，项目和验证记录都为空。两个可选字段的比较结果为相等，随后却读取不存在的验证记录。该异常来自扩展状态组装，不代表本地重置失败。

读取到期时间前，现要求项目和验证记录都存在，且项目标识相同。首次打开首页、完成重置后连续刷新、重新授权都不应显示该异常。

## 自测

| 检查 | 结果 |

| 扩展语法与单测 | 109 passed，0 failed |

| 最终 VSIX 联调 | 退出码 0；最终提取包在 VS Code 1.138.0 Extension Host 通过首次打开、完成后连续刷新、重新授权及外部 CLI 重置观察 |
| 冻结程序与离线安装 | 最终 VSIX 中的服务及官方隧道程序离线安装通过；受限 PATH、配对、MCP 读取、客户端重连与错误分类通过 |
| 冻结重置 | 服务停止、重启后空授权、旧管理/MCP 令牌拒绝、幂等重置和原文件/恢复内容保留通过 |

最终安装包测试使用隔离用户目录，覆盖首次打开时无项目、重置取消、两个项目的清理、完成后连续刷新三次、旧令牌拒绝、显式重新授权和外部 CLI 重置观察。

模拟其他窗口清理仍未结束时，可以暂时显示服务停止提示；不把这个中间状态要求为已经恢复完成。完成后页面错误字段应为空。

核心服务业务逻辑没有改变，源码版本随安装包同步为 0.8.1。本轮没有重跑 216 项 Python 全量测试；0.8.0 的历史完整结果仍在原验收报告中。
