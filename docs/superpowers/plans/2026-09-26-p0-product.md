# P0 Product Implementation Plan

> **For agentic workers:** Execute this plan task-by-task with red/green tests and review each boundary before moving on.

**Goal:** Make first-time web setup, local service control, diagnosis, and upgrades usable from the VS Code home page without a terminal.

**Architecture:** Keep service ownership and snapshots in the existing Python runtime. Add small, testable VS Code helpers for web configuration and Windows login startup, then wire them into the existing home view. Never put OAuth secrets in config files, URLs, command arguments, diagnostics, or logs.

**Tech Stack:** Node.js VS Code extension, Python CLI/runtime, Windows Credential Manager via keyring, Windows HKCU Run, existing pytest/node:test suites.

**Spec:** User-approved P0 requirements in this task: first-time guided web connection, visible service management and recovery, safe diagnosis/repair, and upgrade with backup and rollback.

## Global Constraints

- Existing authorized projects and tokens survive web setup and upgrade.
- Service start/stop and repair operate only on a verified owned process.
- ChatGPT account capability and real tool call require user-side verification; local probes must not claim success for them.
- Default diagnostic export excludes paths, secrets, source, OAuth responses, and identities.
- Never run integration tests against the user's live `%LOCALAPPDATA%\AI Zhagan` state.
